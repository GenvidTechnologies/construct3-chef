# Wiki Index

This is construct3-chef's **only** documentation tier: since the `docs/`
consolidation of 2026-08-20 (ADR
[0028](https://github.com/GenvidTechnologies/construct3-chef/blob/main/wiki/decisions/0028-documentation-consolidated-into-the-wiki-tier.md)) all
documentation lives under `wiki/` in the repository. `CLAUDE.md` keeps only
the always-loaded operating context and routes here for everything else.

Only part of the wiki ships (ADR
[0071](https://github.com/GenvidTechnologies/construct3-chef/blob/main/wiki/decisions/0071-only-the-external-wiki-tier-ships-and-is-served.md)).
The reference manuals in the Reference section ship with the npm package and
are served as `docs:///` resources. The architecture, process and decision
sections, the schema and the practice note stay in the repository. They are
linked here by their GitHub URLs.

`/gvt-dev:maintain-wiki` keeps this list current: a new page is added here (or
to its subdirectory's own `index.md`) when it's created, and `lint` flags any
page listed in **no** index. Each entry's description is the linked page's
frontmatter `description`, so the index and the page can't drift — the indexes
are generated by `npm run wiki:index`, never hand-edited. See
[wiki-schema.md](https://github.com/GenvidTechnologies/construct3-chef/blob/main/wiki/wiki-schema.md) for the page format and maintenance rules.

## C3 platform reference (the *why* behind the gotchas)

C3 platform reference — event-sheet & layout JSON structure, the scripting API,
the TS async/concurrency model — lives in the **gvt-construct3** Claude Code
plugin at `${CLAUDE_PLUGIN_ROOT}/docs/c3/*`, not here. construct3-chef owns the
*tooling* knowledge above; the plugin owns the *platform* knowledge.
